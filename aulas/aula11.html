Orquestrando Ações: O Próximo Nível do Scripting

Na aula anterior, demos os primeiros passos com C#, movendo um objeto com lógica dentro do `Update()`. No entanto, a maioria das ações em um jogo não acontece continuamente. Elas acontecem em resposta a algo (um evento) ou ao longo de um período específico de tempo (uma sequência).

Como fazemos para que uma porta se abra após o jogador pisar em uma placa de pressão? Como criamos um inimigo que ataca, espera e ataca novamente? A resposta está em organizar nosso código de forma mais inteligente e dominar as ferramentas que a Unity nos oferece para controlar o tempo.

"A complexidade de um bom gameplay não vem de um código complicado, mas de regras simples que interagem de maneiras interessantes ao longo do tempo."
— Adaptado de Schuytema, P., "Design de games: uma abordagem prática"

Hoje, vamos aprender a criar blocos de código reutilizáveis (métodos), a reagir a eventos do mundo do jogo (como colisões) e a orquestrar ações sequenciais com a poderosa ferramenta das corrotinas.

Ciclo de Execução da Unity

Awake → OnEnable → Start → Update → LateUpdate → OnDisable → OnDestroy é a ordem típica de eventos chamados pela Unity. Use:

  • Awake: inicialização essencial (referências).
  • Start: começa após todos os Awake concluírem.
  • Update: lógica por frame (entrada do jogador).
  • FixedUpdate: física/forças em Rigidbody.
  • LateUpdate: câmera que segue o jogador (roda depois do Update).

Referência: ordem e recomendações de uso na documentação oficial da Unity (execução por evento).

Métodos e Eventos: Organização e Reação

1. Métodos: Organizando seu Código

Um método (ou função) é um bloco de código nomeado que pode ser chamado de outras partes do seu script. Usá-los torna o código mais limpo, legível e reutilizável.

Anatomia de um Método:

// Visibilidade | Tipo de Retorno | Nome (Parâmetros)
public void MoverJogador(float velocidade) 
{
    // Corpo do método
}

Exemplo Prático: Refatorando o `Update`

Vamos pegar a lógica de movimento da aula passada e encapsulá-la em um método. Isso torna o `Update` mais limpo e a lógica de movimento reutilizável. 

// Refactored code with a dedicated method
public class MovimentoRefatorado : MonoBehaviour
{
    public float velocidade = 5f;

    void Update()
    {
        // Update is now clean and just calls the method
        ProcessarInput();
    }

    // A new method to handle movement logic
    void ProcessarInput()
    {
        float movimentoHorizontal = Input.GetAxis("Horizontal");
        Vector3 direcao = Vector3.right * movimentoHorizontal;
        transform.Translate(direcao * velocidade * Time.deltaTime);
    }
}

2. Eventos: Reagindo à Física

Unity possui métodos de evento que são chamados automaticamente em resposta a acontecimentos, como colisões físicas. Isso nos permite criar reações sem precisar verificar tudo a cada frame no `Update`.

O conceito é baseado no Padrão Observer, onde um objeto (o "Observado", como um colisor) notifica outros objetos (os "Observadores", como seus scripts) quando algo importante acontece.

Evento de Trigger: `OnTriggerEnter`

Este método é chamado quando um GameObject com um Collider (marcado como "Is Trigger") entra em contato com outro Collider. É perfeito para áreas de ativação, como placas de pressão ou portais. 

// Script to be placed on a trigger zone (e.g., a pressure plate)
public class PlacaDePressao : MonoBehaviour
{
    // This event method is called by Unity automatically
    private void OnTriggerEnter(Collider other)
    {
        // 'other' is the Collider of the object that entered the trigger
        // We can check its tag to see if it's the player
        if (other.CompareTag("Player"))
        {
            Debug.Log("O Jogador pisou na placa!");
            // Here we would call a method to open a door, for example
        }
    }
}

Eventos: C# (delegate) vs UnityEvent

C# event/delegate dá desempenho e segurança de tipo; UnityEvent permite conectar callbacks no Inspector (bom para designers).

Exemplo (C# event)

public class Porta : MonoBehaviour
{
    public event System.Action AoAbrir;

    public void Abrir()
    {
        // ... animação/efeito ...
        AoAbrir?.Invoke(); // notifica inscritos
    }
}

public class HUDPorta : MonoBehaviour
{
    public Porta porta;
    void OnEnable()  => porta.AoAbrir += MostrarMensagem;
    void OnDisable() => porta.AoAbrir -= MostrarMensagem;

    void MostrarMensagem() => Debug.Log("A porta foi aberta!");
}

Exemplo (UnityEvent)

using UnityEngine.Events;

public class BotaoInterativo : MonoBehaviour
{
    public UnityEvent aoClicar;
    void OnMouseDown() => aoClicar?.Invoke();
}

Trigger vs Collision (3D e 2D)

Trigger (sensor)

Marque Is Trigger no Collider. Eventos: OnTriggerEnter/Stay/Exit. Útil para placas de pressão, áreas de dano e portais.

Collision (contato físico)

Colliders sem Is Trigger geram OnCollisionEnter/Stay/Exit. Há resposta física (empurrões/quicar) quando há Rigidbody.

Observação: 2D usa os equivalentes OnTriggerEnter2D / OnCollisionEnter2D.

Corrotinas: Dominando o Tempo

O `Update()` é executado em todos os frames, o que é ótimo para ações contínuas. Mas e se quisermos uma sequência como: "piscar a luz, esperar 1 segundo, piscar de novo"? Fazer isso no `Update()` é complexo. A solução da Unity para isso são as Corrotinas.

Uma corrotina é como um método que pode ser pausado e retomado. Ela permite escrever lógicas sequenciais de forma limpa e legível.

Anatomia de uma Corrotina:

  • O tipo de retorno deve ser IEnumerator.
  • Usa a palavra-chave yield return para pausar a execução.
  • É iniciada com o método StartCoroutine().

Pausas Comuns com `yield return`:

  • yield return null;: Pausa a corrotina e a retoma no próximo frame.
  • yield return new WaitForSeconds(float tempo);: Pausa a corrotina pela quantidade de segundos especificada. Esta é a mais usada para delays.

Exemplo: Luz Piscante 

// Script that makes a light blink using a coroutine
using System.Collections;
using UnityEngine;

public class LuzPiscante : MonoBehaviour
{
    public Light minhaLuz;

    void Start()
    {
        // Start the coroutine. It will run in the "background".
        StartCoroutine(CicloDePiscar());
    }

    IEnumerator CicloDePiscar()
    {
        // An infinite loop to keep the blinking going
        while (true)
        {
            // Turn the light on
            minhaLuz.enabled = true;
            // Pause the execution for 0.5 seconds
            yield return new WaitForSeconds(0.5f);
            // Turn the light off
            minhaLuz.enabled = false;
            // Pause the execution for 0.5 seconds
            yield return new WaitForSeconds(0.5f);
        }
    }
}

Corrotinas: Tempo e Cancelamento

Tempo escalado vs não escalado

  • WaitForSeconds(x) usa Time.timeScale. Se timeScale=0 (pause), a espera “congela”.
  • WaitForSecondsRealtime(x) ignora timeScale (bom para UI/pausa/timeout). 
// Ex.: contagem regressiva que continua mesmo em pause
IEnumerator Contagem(float secs)
{
    yield return new WaitForSecondsRealtime(secs);
    Debug.Log("Tempo real decorrido mesmo com pause.");
}

Referência: WaitForSecondsRealtime na documentação da Unity.

Cancelar/evitar duplicação 

Coroutine rotina;
public void AbrirComDelay(float s)
{
    if (rotina != null) StopCoroutine(rotina);
    rotina = StartCoroutine(AbrirDepois(s));
}

IEnumerator AbrirDepois(float s)
{
    yield return new WaitForSeconds(s);
    // ... abre ...
    rotina = null;
}

Corrotinas iniciadas em um MonoBehaviour são gerenciadas por ele e têm comportamento específico ao habilitar/desabilitar o componente. Veja “Coroutines and disabling” na documentação.

Estudo de Caso: A Porta com Atraso

Vamos unir tudo o que aprendemos para construir o sistema da nossa tarefa: uma placa de pressão que abre uma porta após um pequeno atraso.

Estrutura na Cena:

  • Um GameObject "Jogador" com a tag "Player" e um Rigidbody.
  • Um GameObject "PlacaDePressao" com um Box Collider marcado como "Is Trigger".
  • Um GameObject "Porta" com um Box Collider.

Script 1: PlacaDePressao.cs 

// Attached to the Pressure Plate object
using UnityEngine;

public class PlacaDePressao : MonoBehaviour
{
    // A public reference to the door we want to open
    public Porta portaParaAbrir;

    private void OnTriggerEnter(Collider other)
    {
        if (other.CompareTag("Player"))
        {
            Debug.Log("Player detected! Telling the door to open...");
            // Call the public method on the door script
            portaParaAbrir.AbrirComAtraso();
        }
    }
}

Script 2: Porta.cs 

// Attached to the Door object
using System.Collections;
using UnityEngine;

public class Porta : MonoBehaviour
{
    public float atrasoParaAbrir = 2f; // 2 second delay

    // This is a public method that can be called from other scripts
    public void AbrirComAtraso()
    {
        // Start the coroutine that handles the sequence
        StartCoroutine(SequenciaDeAbertura());
    }

    private IEnumerator SequenciaDeAbertura()
    {
        Debug.Log("Coroutine started. Waiting for delay...");
        // 1. Wait for the specified delay
        yield return new WaitForSeconds(atrasoParaAbrir);

        Debug.Log("Delay finished. Opening the door!");
        // 2. Deactivate the door object to "open" it
        gameObject.SetActive(false);
    }
}

Boas Práticas Rápidas

✔️ Use FixedUpdate para alterar Rigidbody (forças/velocidades).

✔️ Evite iniciar corrotinas repetidas; guarde a referência e cancele quando preciso.

✔️ Em loops infinitos, sempre tenha um yield (ex.: yield return null;).

✔️ Prefira WaitForSecondsRealtime em contagens/tempo de UI durante pause.

📝 Tarefa (TED): Simulando um Evento com Delay

Sua tarefa é recriar um sistema similar ao do estudo de caso, mas com uma pequena variação: uma porta que abre com um atraso após o jogador clicar nela.

Passo a Passo:

  1. Crie uma cena com um objeto "Porta".
  2. Crie um script `PortaInterativa` e anexe-o à porta.
  3. Dentro do script, crie um método `OnMouseDown()`. Este é um evento da Unity chamado quando o usuário clica com o mouse sobre um Collider.
  4. No `OnMouseDown()`, chame `StartCoroutine()` para iniciar uma corrotina de abertura.
  5. Na corrotina, use `yield return new WaitForSeconds()` para criar um delay de 3 segundos.
  6. Após o delay, desative o GameObject da porta para simular sua abertura.
  7. Entrega: Publique o código completo do seu script `PortaInterativa` no fórum do Moodle e comente em uma ou duas frases como o `StartCoroutine()` foi essencial para criar a sequência com tempo de espera.
