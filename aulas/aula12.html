Unidade III – Programação com C# para Games

Plano da Aula

CONTEÚDO

Input System na prática: Action Maps, bindings (teclado/mouse/gamepad), leitura de eventos via C# e vínculo com o personagem.

OBJETIVO

Configurar e usar o Input System para capturar ações do jogador e acionar comportamentos de movimento e interação via script.

METODOLOGIA

Aula prática guiada + pair programming (projeto incremental).

Por que o Input System?

O Input System unifica teclado, mouse, gamepad e toques em um só fluxo de trabalho. Em vez de ler teclas soltas, definimos Ações (ex.: Move, Jump, Interact) e mapeamos diferentes dispositivos para cada uma. Isso facilita remapeamento, suporte a múltiplos joysticks e testes.

“O Input System desacopla a intenção do jogador do hardware, permitindo incluir novos dispositivos sem reescrever a lógica de jogo.”

Input Manager (antigo) × Input System (novo)

Característica Input Manager Input System
Abordagem Eixos/strings Ações/objetos
Configuração Project Settings Asset visual (Action Maps)
Dispositivos Limitado Amplo (gamepads, touch, etc.)
Remapeamento Manual e complexo Nativo
Leitura Polling no Update Eventos + polling quando necessário

Configuração rápida

  1. Projeto Unity URP aberto.
  2. Instale o pacote Input System via Package Manager.
  3. Ative em Edit > Project Settings > Player > Active Input Handling: Input System Package (New) ou Both.
  4. No Project: Create > Input Actions (PlayerControls).
  5. No asset: crie o Action Map Player com Move (Vector2), Jump (Button), Interact (Button).
  6. Bindings (sugestão): Move → WASD/Setas/Left Stick; Jump → Space + South Button; Interact → E + West Button.
  7. Marque Generate C# Class (PlayerControls.cs) e clique Save Asset.
Reinício do editor: ao alternar o backend de input, o Unity reinicia para aplicar o novo sistema em todo o editor e no runtime.
Erros comuns: esquecer de salvar o asset; não habilitar o mapa com Enable(); colisor sem Is Trigger para interações por área.

Mapa de Ações (sugestão)

Action Tipo Bindings (Teclado/Mouse) Bindings (Gamepad) Uso no jogo
Move Value / Vector2 WASD / Setas (2D Vector Composite) Left Stick Direção (X/Z) do personagem
Jump Button Espaço South Button (A/✕) Pular
Interact Button E West Button (X/□) Ativar/Coletar/Usar

Passos rápidos para o Move (Composite 2D)

  1. No Action Map Player, crie a Action Move com Action Type: Value e Control Type: Vector2.
  2. Adicione um Add 2D Vector Composite e nomeie WASD.
  3. Configure: Up=W, Down=S, Left=A, Right=D. Adicione outro composite para setas, se quiser.
  4. Adicione binding de Left Stick [Gamepad].
  5. Salve o asset (Save Asset).
UX de controle: deixe pulo em Space/South Button e ações frequentes em botões confortáveis; planeje remapeamento depois.

Control Schemes & Auto-Switch

Separe dispositivos em Control Schemes (ex.: Keyboard&Mouse e Gamepad) no asset de Input Actions. O PlayerInput pode alternar automaticamente o esquema conforme o último dispositivo usado.

Esquema Dispositivos Uso
Keyboard&Mouse Keyboard, Mouse PC/Desktop
Gamepad XInput/DualShock/DualSense Console/PC com controle 
using UnityEngine;
using UnityEngine.InputSystem;

[RequireComponent(typeof(PlayerInput))]
public class SchemeIndicator : MonoBehaviour
{
    private PlayerInput pi;
    void Awake() { pi = GetComponent<PlayerInput>(); }
    void OnEnable() { pi.onControlsChanged += OnControlsChanged; }
    void OnDisable() { pi.onControlsChanged -= OnControlsChanged; }

    private void OnControlsChanged(PlayerInput _)
    {
        Debug.Log("Esquema ativo: " + pi.currentControlScheme); // "Keyboard&Mouse" ou "Gamepad"
    }
}

Remapeamento (Rebinding) com persistência

Permita ao jogador alterar bindings em runtime e salvar preferências localmente. 

using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.InputSystem.Utilities;

public class SimpleRebind : MonoBehaviour
{
    public InputActionAsset actions; // arraste o asset (PlayerControls)
    public string actionPath = "Player/Jump"; // Action que será remapeada

    private InputAction GetAction() => actions.FindAction(actionPath, throwIfNotFound:true);

    void Awake()
    {
        // Carrega overrides salvos (se houver)
        var json = PlayerPrefs.GetString("rebinds", "");
        if (!string.IsNullOrEmpty(json)) actions.LoadBindingOverridesFromJson(json);
    }

    public void StartRebind()
    {
        var action = GetAction();
        action.Disable();
        action.PerformInteractiveRebinding()
              .WithControlsExcluding("<Mouse>/position")
              .WithCancelingThrough("<Keyboard>/escape")
              .OnComplete(op => { action.Enable(); op.Dispose(); Save(); Debug.Log("Rebind concluído: " + action.bindings[action.GetBindingIndexForControl(action.controls[0])].effectivePath); })
              .Start();
    }

    private void Save()
    {
        var json = actions.SaveBindingOverridesAsJson();
        PlayerPrefs.SetString("rebinds", json);
    }
}

Padrões de leitura no C#

Padrão A — Classe gerada + polling no Update + eventos

Usa a classe PlayerControls gerada. Lê Move a cada frame e escuta Jump/Interact. 

using UnityEngine;
using UnityEngine.InputSystem;

[RequireComponent(typeof(Rigidbody))]
public class PlayerController : MonoBehaviour
{
    public float moveSpeed = 5f;
    public float jumpForce = 5f;

    private Rigidbody rb;
    private PlayerControls controls;
    private Vector2 moveInput;
    private bool jumpQueued;

    void Awake()
    {
        rb = GetComponent<Rigidbody>();
        controls = new PlayerControls();
    }

    void OnEnable()
    {
        controls.Player.Enable();
        controls.Player.Jump.performed += OnJump;
        controls.Player.Interact.performed += OnInteract;
    }

    void OnDisable()
    {
        controls.Player.Jump.performed -= OnJump;
        controls.Player.Interact.performed -= OnInteract;
        controls.Player.Disable();
    }

    void Update()
    {
        moveInput = controls.Player.Move.ReadValue<Vector2>();
    }

    void FixedUpdate()
    {
        Vector3 v = new Vector3(moveInput.x, 0f, moveInput.y) * moveSpeed;
        rb.MovePosition(rb.position + v * Time.fixedDeltaTime);

        if (jumpQueued)
        {
            rb.AddForce(Vector3.up * jumpForce, ForceMode.Impulse);
            jumpQueued = false;
        }
    }

    private void OnJump(InputAction.CallbackContext ctx)
    {
        if (ctx.performed) jumpQueued = true;
    }

    private void OnInteract(InputAction.CallbackContext ctx)
    {
        if (ctx.performed) Debug.Log("Interagir!");
    }
}

Padrão B — Componente PlayerInput (Send Messages)

Adicione PlayerInput ao Player, arraste o asset, Default Map: Player, Behavior: Send Messages. 

using UnityEngine;
using UnityEngine.InputSystem;

public class PlayerInputController : MonoBehaviour
{
    public float speed = 5f;
    private Vector2 move;

    public void OnMove(InputValue value) { move = value.Get<Vector2>(); }
    public void OnJump(InputValue value) { if (value.isPressed) Debug.Log("Pulo!"); }
    public void OnInteract(InputValue value) { if (value.isPressed) Debug.Log("Interagir!"); }

    void Update()
    {
        Vector3 dir = new Vector3(move.x, 0f, move.y);
        transform.Translate(dir * speed * Time.deltaTime, Space.World);
    }
}

Alternativa — CharacterController com eventos performed/canceled

Leitura via callbacks e movimentação com CharacterController. 

using UnityEngine;
using UnityEngine.InputSystem;

[RequireComponent(typeof(CharacterController))]
public class CCPlayerController : MonoBehaviour
{
    private PlayerControls controls;
    private CharacterController cc;
    private Vector2 moveInput;
    public float speed = 8f;

    void Awake()
    {
        cc = GetComponent<CharacterController>();
        controls = new PlayerControls();
    }

    void OnEnable()
    {
        controls.Player.Enable();
        controls.Player.Move.performed += OnMovePerformed;
        controls.Player.Move.canceled += OnMoveCanceled;
    }

    void OnDisable()
    {
        controls.Player.Move.performed -= OnMovePerformed;
        controls.Player.Move.canceled -= OnMoveCanceled;
        controls.Player.Disable();
    }

    private void OnMovePerformed(InputAction.CallbackContext ctx)
    {
        moveInput = ctx.ReadValue<Vector2>();
    }

    private void OnMoveCanceled(InputAction.CallbackContext ctx)
    {
        moveInput = Vector2.zero;
    }

    void Update()
    {
        Vector3 dir = new Vector3(moveInput.x, 0f, moveInput.y);
        cc.Move(dir * speed * Time.deltaTime);
    }
}

Checklist de validação

  • Pacote instalado e Active Input Handling configurado.
  • Asset PlayerControls salvo (e classe gerada, se usar Padrão A).
  • Bindings de teclado e gamepad testados (Window > Analysis > Input Debugger).
  • Enable() chamado no mapa/ação (Padrão A) ou PlayerInput ativo (Padrão B).
  • Com Rigidbody, mova em FixedUpdate(); com CharacterController, use Update().
Debug: coloque Debug.Log() nos handlers e confira eventos no Input Debugger.

Navegação de UI (Menus) com o Input System

Para navegar menus com teclado/mouse/gamepad, use o InputSystemUIInputModule no EventSystem e um Action Map "UI".

Action (UI) Tipo Bindings (Teclado/Mouse) Bindings (Gamepad) Uso
Navigate Value / Vector2 Setas / WASD Left Stick / D-Pad Mover foco
Submit Button Enter / Space South Button (A/✕) Selecionar
Cancel Button Esc East Button (B/○) Voltar
Point Value / Vector2 Mouse Position — Cursor
Click Button Left Mouse Button South Button (A/✕) Clique
  1. Crie no asset um Action Map "UI" com as actions acima.
  2. Na cena, adicione EventSystem e troque o componente de entrada para Input System UI Input Module.
  3. Arraste seu asset de Input Actions para o campo Actions Asset e mapeie Point/Navigate/Submit/Cancel/Click.

Use a ação Pause para alternar entre o mapa Player (jogo) e UI (menu): 

using UnityEngine;
using UnityEngine.InputSystem;

[RequireComponent(typeof(PlayerInput))]
public class ToggleUIActionMap : MonoBehaviour
{
    public GameObject pauseMenu; // painel Canvas do menu
    private PlayerInput pi;
    private bool paused;

    void Awake() { pi = GetComponent<PlayerInput>(); }

    // Vincule esta função à Action "Pause" (performed)
    public void OnPause(InputValue v)
    {
        if (!v.isPressed) return;
        paused = !paused;
        pauseMenu.SetActive(paused);
        pi.SwitchCurrentActionMap(paused ? "UI" : "Player");
        Time.timeScale = paused ? 0f : 1f;
    }
}

Multiplayer Local com PlayerInputManager

Permite que jogadores entrem pressionando um botão em controles diferentes. Cada jogador instancia um Player Prefab com PlayerInput.

  1. Crie um Player Prefab com PlayerInput configurado (Default Map: Player).
  2. Na cena, adicione um objeto vazio com PlayerInputManager:
    • Join Behavior: Join Players When Button Is Pressed
    • Player Prefab: seu prefab do jogador
  3. (Opcional) Adicione o script abaixo para definir posição/cor ao entrar. 
using UnityEngine;
using UnityEngine.InputSystem;

public class LocalMPSetup : MonoBehaviour
{
    public Transform[] spawnPoints; // arraste pontos de spawn
    private int nextIndex = 0;

    void OnEnable()
    {
        PlayerInputManager.instance.onPlayerJoined += OnPlayerJoined;
    }

    void OnDisable()
    {
        PlayerInputManager.instance.onPlayerJoined -= OnPlayerJoined;
    }

    private void OnPlayerJoined(PlayerInput player)
    {
        // posiciona no próximo spawn
        if (spawnPoints != null && spawnPoints.Length > 0)
        {
            var t = spawnPoints[nextIndex % spawnPoints.Length];
            player.transform.SetPositionAndRotation(t.position, t.rotation);
            nextIndex++;
        }

        // exemplo visual por jogador
        var rend = player.GetComponentInChildren<Renderer>();
        if (rend != null)
        {
            var c = Random.ColorHSV(0f,1f, .7f,1f, .8f,1f);
            rend.material.color = c;
        }

        Debug.Log($"Jogador {player.playerIndex} entrou via {player.currentControlScheme}");
    }
}

Cada jogador terá seu próprio PlayerInput e conjunto de ações. Para UI compartilhada, mantenha um único EventSystem com InputSystemUIInputModule e esquema ativo alternado automaticamente por dispositivo.
